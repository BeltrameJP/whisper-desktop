# ADR 0012 — CI/CD with GitHub Actions

- **Status:** Accepted
- **Date:** 2026-08-16

## Context

Whisper Desktop must ship to Windows, macOS, and Linux. The Python unit tests should be verified automatically before code is merged, and packaging is build-per-OS (ADR 0006), so the macOS and Linux binaries can only be produced on those platforms. Both concerns should be automated and reproducible.

## Decision

Two GitHub Actions workflows under `.github/workflows/`:

- **`test.yml`** — triggers on `push`.
  - A `lint` job (ubuntu-latest) runs `ruff check .` and `ruff format --check .` first, failing fast before any tests run.
  - A `test` job (`needs: lint`) runs `poetry install --with test` + `pytest` on a 3-OS matrix: `ubuntu-latest`, `windows-latest`, `macos-latest`.
- **`release.yml`** — triggers on `workflow_dispatch` (manual only, to avoid an endless version-bump loop).
  - A `build` job matrix produces the three installers with PyInstaller:
    - `windows-latest` → `WhisperDesktop.exe` (x64, `--onefile`)
    - `ubuntu-latest` → ELF binary (`--onefile`, after `apt-get install libportaudio2`)
    - `macos-14` → arm64 `.app` bundle via `WhisperDesktop.spec`, zipped (after `brew install portaudio`)
  - Each build bundles faster-whisper, ctranslate2, sounddevice, scipy, and Tcl/Tk via `--collect-all`.
  - A `release` job tags `v{version}` (read from `pyproject.toml`), publishes a GitHub Release, and attaches the three binaries.
  - A `bump-version` job then opens a `[Chore] Update version to X` pull request applying a patch bump to `pyproject.toml` so the next release is ready.

Poetry is pinned in CI to the same version that generated the lockfile.

## Consequences

- Tests run on all three OSes before merge.
- macOS and Linux binaries are produced by CI on their native platforms (ADR 0006); they cannot be built on a Windows-only dev machine.
- Releases are manual, so merging the auto-created `[Chore]` bump PR does not re-trigger a release.
- Binaries are unsigned and not notarized; macOS users must bypass Gatekeeper (right-click → Open).
- A new GitHub Actions release requires a version present in `pyproject.toml` that has not yet been tagged.
